# Пазлы с животными: план работ

Nov 12, 2026 · @Dmytro

## Обзор продукта и ключевые решения

Игра-пазл с животными на Flutter + Flame: 11 категорий по 20–30 картинок, по 5 бесплатных в каждой, остальное открывает разовая покупка «Полная версия» за $4.99. Первый релиз — Android, только горизонтальная ориентация, телефоны и планшеты.

Ключевые решения, которые этот план фиксирует:

- **Тип пазла — классический jigsaw с процедурной нарезкой.** Любая сгенерированная картинка режется кодом на кусочки, поэтому не нужно рисовать слои и детали для каждого животного вручную. Это главное условие, чтобы 220–330 картинок были посильны.
- **Бесплатные картинки внутри приложения, платные — загрузка с CDN.** Так APK остаётся лёгким, а новые картинки можно добавлять без выпуска обновления.
- **Разовая покупка через RevenueCat поверх Google Play Billing.** Одна покупка навсегда открывает все картинки; серверная проверка покупок без своего бэкенда.
- **Без аккаунтов и своего сервера в версии 1.0.** Прогресс хранится локально, покупка восстанавливается через Google Play.
- **Архитектура готова к iOS,** но в 1.0 делается и тестируется только Android.
- **Языки 1.0: украинский, английский и русский.** Язык берётся из системы, если он не поддерживается, используется английский; в настройках язык можно сменить вручную.

Правила наполнения:

- Единица контента — картинка-сцена, а не вид животного. Категории по среде обитания (море, саванна, джунгли, пустыня) и по группе животных (акулы, змеи, пауки, кошачьи, псовые) пересекаются, поэтому одно животное может появиться в двух категориях, но в разных сценах: например, львица со львятами в саванне и лев крупным планом в кошачьих. Повторы фиксируются в общем списке до генерации.
- Внутри категории сцены не повторяются. Для узких категорий (акулы, пауки, змеи) разнообразие дают сцены и ракурсы, а не редкие виды: их ребёнок не отличит, а генератор не нарисует достоверно.
- Первые 5 картинок категории — самые узнаваемые и красивые: они продают полную версию.
- Названия категорий и животных локализуются на украинский, английский и русский (uk, en, ru), в коде используются только id.

## Игровая механика пазла

Игрок выбирает категорию, картинку и сложность, затем собирает jigsaw-пазл перетаскиванием кусочков на поле. Кусочки нарезаются кодом из одной картинки, формы с «ушками» генерируются по сетке.

Игровой экран:

- Слева или по центру — поле с полупрозрачным контуром или бледной подложкой картинки (включается в настройках как подсказка).
- Справа или снизу — лоток с перемешанными кусочками, при большом количестве лоток прокручивается. Во Flame нет готового прокручиваемого списка, поэтому лоток — отдельный компонент, в котором прокрутка лотка отличается от начала перетаскивания кусочка (например, по направлению жеста или задержке).
- Кусочек «примагничивается», если отпущен ближе 25–30% своего размера к своему месту (фиксированный порог в пикселях на «Лёгком» слишком мал, а на «Эксперте» почти равен половине кусочка): анимация `MoveEffect`, звук щелчка, лёгкая вибрация.
- Кусочки не поворачиваются (для детской аудитории вращение усложняет игру без пользы).
- После сборки — короткая анимация, конфетти, звук и звезда за картинку.
- Незаконченный пазл сохраняется на диск при сворачивании приложения и продолжается с того же места, даже если система выгрузила приложение из памяти.

Уровни сложности (выбор перед стартом):

| Уровень | Сетка | Кусочков | Для кого |
| --- | --- | --- | --- |
| Лёгкий | 3 × 2 | 6 | Малыши 3–5 лет |
| Средний | 4 × 3 | 12 | Дети 5–8 лет |
| Сложный | 6 × 4 | 24 | Дети постарше и взрослые |
| Эксперт | 8 × 6 | 48 | Только на планшете или по желанию |

Прогресс: для каждой картинки хранится лучший пройденный уровень сложности, в списке категорий показывается количество собранных картинок. Звуки: фоновая музыка и эффекты с отдельными переключателями.

## Технический стек и архитектура

Меню, каталог, пейволл и настройки — обычные Flutter-виджеты; Flame используется только на экране сборки пазла через `GameWidget`.

| Задача | Решение |
| --- | --- |
| Игровой экран | flame, flame\_audio |
| Состояние | flutter\_riverpod, flame\_riverpod для связи с игровым экраном |
| Навигация | go\_router |
| Покупки | purchases\_flutter (RevenueCat) |
| Локальные данные и прогресс | shared\_preferences для настроек, JSON-файл в каталоге приложения для прогресса и незаконченного пазла (данных мало, отдельная база не нужна) |
| Загрузка платных картинок | dio + path\_provider + crypto (sha256), свой кэш на диске |
| Локализация | flutter gen-l10n (ARB-файлы) |
| Аналитика и краши | Crashlytics; Firebase Analytics в 1.0 не используется из-за политики Google Play для семей, метрики выручки и конверсии берутся из RevenueCat |
| CDN для картинок | Firebase Storage или Cloudflare R2 |

Структура проекта:

```
lib/
  app/            # MaterialApp, роутер, тема
  core/           # константы, утилиты, логирование
  features/
    catalog/      # категории, список картинок, манифест
    puzzle/       # Flame-игра: нарезка, кусочки, поле, лоток
    progress/     # хранение прогресса
    subscription/ # RevenueCat, пейволл, родительский контроль
    content/      # загрузка и кэш картинок с CDN
    settings/
  l10n/
assets/
  images/free/    # 55 бесплатных картинок
  thumbs/         # превью картинок первого релиза (размытые для закрытых)
  audio/
  manifest.json   # встроенная копия манифеста
tools/
  image_pipeline/ # скрипты генерации и обработки картинок
```

Манифест контента — один JSON, встроенная копия в assets и свежая версия на CDN:

```json
{
  "version": 3,
  "minAppVersion": "1.0.0",
  "categories": [
    {
      "id": "sea",
      "title": {"uk": "Морські тварини", "en": "Sea animals", "ru": "Морские животные"},
      "puzzles": [
        {"id": "sea_turtle", "title": {"uk": "Черепаха", "en": "Turtle", "ru": "Черепаха"},
         "free": true, "asset": "images/free/sea_turtle.webp",
         "thumb": "thumbs/sea_turtle.webp"},
        {"id": "sea_whale", "title": {"uk": "Кит", "en": "Whale", "ru": "Кит"},
         "free": false, "url": "https://cdn.example.com/sea/sea_whale.webp",
         "thumbUrl": "https://cdn.example.com/sea/sea_whale_thumb.webp",
         "sha256": "..."}
      ]
    }
  ]
}
```

Правила манифеста:

- `minAppVersion` — минимальная версия приложения, которая понимает схему. Более старые версии не применяют свежий манифест с CDN и остаются на встроенном.
- Картинки, добавленные после релиза, приходят только с CDN: у таких записей вместо `asset` и `thumb` указаны `url` и `thumbUrl`, в том числе у новых бесплатных картинок.
- Ссылки на платные картинки лежат в открытом манифесте, и скачать их может кто угодно. Это осознанно принятый риск: защита контента стоит дороже возможных потерь.

Нарезка пазла — чистая Dart-логика без Flame (генерация форм кусочков по сетке и сиду), чтобы её можно было покрыть юнит-тестами. При нарезке каждый кусочек один раз отрисовывается в отдельное изображение (`PictureRecorder` → `toImage`), а не обрезается по контуру в каждом кадре: это нужно для 60 FPS при 48 кусочках на слабом телефоне.

Бюджет размера: 55 бесплатных картинок 2048 × 1536 в WebP — примерно 20–30 МБ, превью — ещё около 10 МБ. Ориентир — AAB до 50 МБ, размер сборки проверяется на каждом этапе.

## Горизонтальный режим: телефон и планшет

Приложение работает только в горизонтальной ориентации, один AAB для всех устройств. Главная сложность — разные пропорции: телефоны около 20:9, планшеты от 16:10 до 4:3.

Ориентация:

- В `AndroidManifest.xml` для активности: `android:screenOrientation="sensorLandscape"` (поворот на 180° разрешён).
- Там же для приложения: `android:appCategory="game"`. Начиная с Android 16 при `targetSdk 36` система на больших экранах (короткая сторона от 600 dp) игнорирует ограничения ориентации, а игры, по документации, из этого правила исключены. Проверить по актуальной документации Android и на эмуляторах планшета и складного телефона; раскладка не должна ломаться, даже если система всё же повернёт экран.
- В `main()`: `SystemChrome.setPreferredOrientations([DeviceOrientation.landscapeLeft, DeviceOrientation.landscapeRight])`.
- Полноэкранный режим `SystemUiMode.immersiveSticky` на игровом экране.

Раскладка игрового экрана:

- Картинки пазлов генерируются в пропорции 4:3 (например, 2048 × 1536): она одинаково хорошо смотрится на обоих типах устройств.
- Поле пазла масштабируется по высоте доступной области, свободное место по ширине отдаётся лотку с кусочками.
- На телефоне (20:9) лоток справа узкой колонкой, на планшете (4:3) лоток снизу или справа в зависимости от свободного места. Порог выбирается по соотношению сторон.
- Минимальный размер кусочка для касания — около 48 логических пикселей. Уровень сложности показывается, только если кусочки на этом устройстве не мельче порога, иначе он скрыт. По оценке, на телефоне с короткой стороной 360 dp поле 4:3 по высоте даёт кусочек около 55–60 dp при сетке 8 × 6, так что «Эксперт» обычно доступен и на телефонах, а скрываться будет только на самых маленьких экранах.
- Учитываются вырезы и системные панели через `MediaQuery.padding` и `SafeArea`.

Меню и каталог — адаптивная сетка карточек: количество колонок считается от ширины (`LayoutBuilder`), например 3 колонки на телефоне и 4–5 на планшете.

Матрица проверки на эмуляторах: телефон 20:9 (Pixel 8 или аналог), маленький телефон 16:9 (около 360 dp по короткой стороне), планшет 16:10 (10–11 дюймов), планшет 4:3, а также складной телефон в развёрнутом виде.

## Монетизация: разовая покупка «Полная версия»

«Полная версия» — разовая покупка за $4.99 (non-consumable): навсегда открывает все картинки во всех категориях, в том числе те, что позже придут с CDN. Покупки идут через Google Play Billing, проверку и статус берёт на себя RevenueCat.

Настройка:

- В Play Console: разовый продукт (in-app product) `full_version` за $4.99, цены по странам — автоматический пересчёт. Создать его можно только после загрузки сборки с окончательным `applicationId` в любой трек тестирования.
- Страны распространения: только те, где Google Play принимает оплату. Возможность оплаты зависит от страны покупателя, а не разработчика: например, пользователи из России сейчас не могут оплачивать покупки в Google Play, поэтому включать такие страны в 1.0 нет смысла.
- В RevenueCat: entitlement `full`, offering `default` с пакетом lifetime → `full_version`. В коде проверяется только entitlement, а не id продукта — так позже можно поменять продукт или цену без изменений логики.
- Возможные скидки и наборы по категориям — решение после релиза по данным конверсии.

Поведение в приложении:

- Закрытые картинки видны в каталоге как размытые превью с замком. Нажатие открывает пейволл.
- Перед пейволлом — **родительский контроль**: простая задача для взрослого (например, «введите цифрами: сорок семь»). Это защищает детей от случайных покупок и ожидается от детских приложений.
- На пейволле: что входит в полную версию, цена в местной валюте из магазина, пометка «разовая покупка, без подписки», ссылки на политику конфиденциальности и условия.
- Кнопка «Восстановить покупки» в пейволле и в настройках.
- Переустановка: проверить, восстанавливает ли RevenueCat покупку анонимного пользователя автоматически при первом запуске или только по кнопке «Восстановить покупки», и записать фактическое поведение в критерий Этапа 5.
- Купленная версия работает без интернета за счёт кэша RevenueCat SDK, собственный кэш статуса не нужен.
- Возврат денег (refund) в Google Play отзывает entitlement; приложение реагирует только на его активность, и картинки снова закрываются.

Тестирование: лицензионные тестировщики в Play Console (покупки без списания денег), sandbox-режим RevenueCat, проверка сценариев покупки, отмены покупки, восстановления, переустановки и возврата.

## Пайплайн генерации картинок

Картинки генерируются скриптом по эталонной картинке стиля (image-to-image), а затем проходят автоматическую обработку и ручную проверку. На каждую картинку генерируется один вариант, заново генерируется только брак. Рассчитывайте примерно на 1,3–1,5 генерации на одну финальную картинку, то есть около 300 генераций на 220 картинок; оценка уточняется по доле брака в пробной партии.

Генератор — Nano Banana 2 Lite (`gemini-3.1-flash-lite-image`) через Gemini API. В каждый запрос уходят эталон стиля и текстовый промпт. Цена около $0.034 за картинку, то есть около $10 на 220 картинок. Модель отдаёт картинки около 1K (пробная партия — 1200 × 896), поэтому в обработке картинка увеличивается до 2048 × 1536.

Эталон стиля:

- Глобальный эталон — `docs/puzzle_refs/style_anchor.png` (акула-молот, сгенерирована Nano Banana 2 Lite по стоковой иллюстрации). Стоковая картинка использовалась один раз, чтобы получить этот эталон. В проект она не кладётся и в пакетную генерацию не отправляется, потому что прав на неё у нас нет.
- Эталон категории — первая утверждённая картинка категории. Он идёт в запрос вторым референсом и держит единый фон и палитру внутри категории.
- Эталон меняется только вручную. Если эталон заменён, уже утверждённые картинки категории проверяются заново на совпадение стиля.

Единый стиль (подробно — `docs/puzzle_refs/STYLE.md`):

- Мультяшная детская иллюстрация: жирный тёмный контур, мягкая заливка с объёмом, яркие насыщенные цвета, большие выразительные глаза с бликами, улыбка.
- Без пугающих поз и острых зубов (особенно пауки, змеи, акулы): рот закрыт или открыт в улыбке без клыков.
- Одно животное крупно, в полный рост, 40–60% кадра. Детали распределены по всему кадру: для jigsaw плохо работают большие однотонные области.
- Пропорция 4:3, без текста, подписей, рамок и водяных знаков.

Шаблон промпта — `tools/image_pipeline/prompt.txt`: стиль из эталона (жирный контур, мягкая заливка, яркие цвета, большие глаза), «бери только стиль, не животное и не композицию», затем животное, среда и сцена из CSV, детали по всему кадру, без зубов, текста и рамок, 4:3.

Этапы:

1. Список животных: `tools/image_pipeline/animals.csv` с колонками id, категория, название uk/en/ru, среда обитания, сцена, флаг free, порядок.
2. Генерация: скрипт читает CSV, отправляет в Gemini API промпт, глобальный эталон и эталон категории (если он уже есть), сохраняет один вариант в `raw/`. Картинки, у которых уже есть утверждённый вариант, пропускаются. Ключ API берётся из переменной окружения.
3. Проверка: простая HTML-страница или CLI, где каждую картинку принимают или отмечают браком по чек-листу. Принятые попадают в `selected/`, брак удаляется из `raw/` и при следующем запуске генерируется заново. Первая принятая картинка категории становится её эталоном. Если картинка бракуется 3 раза подряд, меняется сцена или промпт в CSV.
4. Обработка: обрезка до 4:3 (из 1200 × 896 — до 1195 × 896 по центру), ресайз Lanczos до 2048 × 1536 (увеличение примерно в 1,7 раза; если на планшете контуры окажутся мыльными — апскейл Real-ESRGAN anime), WebP с качеством около 85, превью 400 × 300 и размытое превью для закрытых картинок, подсчёт sha256.
5. Манифест: скрипт обновляет `manifest.json`, бесплатные картинки копируются в `assets/images/free/`, платные загружаются на CDN.

Перед массовой генерацией: сгенерировать 5–10 картинок из разных категорий, прогнать обработку и собрать пазл «Эксперт» на планшете. Цель — убедиться, что после увеличения контуры остаются чёткими, а стиль держится между категориями. Если нет, сравнить с Nano Banana 2 (без Lite), который отдаёт большее разрешение.

Чек-лист ручной проверки каждой картинки:

- [ ] Анатомия верная: у пауков 8 ног, у змей нет конечностей, правильное число лап, плавников и пальцев
- [ ] Нет текста, артефактов, лишних или слитых объектов, лишних глаз на камнях, ракушках и растениях
- [ ] Контур сплошной и одной толщины, без размытых участков после увеличения
- [ ] Стиль совпадает с эталоном и остальной категорией
- [ ] Животное узнаваемо, не пугает ребёнка, нет острых зубов
- [ ] Детали есть по всему кадру, в том числе в углах

Лицензии: перед массовой генерацией прочитать условия Gemini API о коммерческом использовании сгенерированных картинок в платном приложении. Картинки Gemini содержат невидимый водяной знак SynthID; это не мешает игре, но стоит учесть при публикации. Стоковую иллюстрацию-референс не использовать в генерации и не распространять. Я не юрист, поэтому условия лучше прочитать у самого сервиса.

## Этапы разработки

Разработка разбита на 8 этапов, каждый заканчивается проверяемым результатом. Этап 3 (картинки) можно вести параллельно с этапами 1–2: пока кода нет, для пазла хватит 5–10 тестовых картинок. Закрытое тестирование в Google Play стартует сразу после Этапа 2, чтобы обязательные 14 дней шли параллельно с этапами 3–7.

### Этап 0. Каркас проекта

- Flutter-проект, Android `minSdk` по требованиям текущего Flutter и плагинов (скорее всего 24 или выше), ориентация landscape с `android:appCategory="game"`, иконка-заглушка.
- Зависимости из раздела про стек, структура папок, `flutter_lints` или `very_good_analysis`.
- `CLAUDE.md` с правилами проекта. Ключ подписи хранится вне папки проекта.
- Локализация через `gen-l10n` с первого дня: ARB-файлы uk, en и ru, в виджетах нет строк, написанных напрямую.

Готово, когда: `flutter analyze` и `flutter test` чистые, приложение запускается на эмуляторе телефона и планшета в горизонтальном режиме, в том числе на планшете с Android 16.

### Этап 1. Ядро пазла

- Генератор нарезки: сетка, формы кусочков с «ушками» по сиду, расчёт целевых позиций (чистый Dart, юнит-тесты).
- Flame-игра: поле, лоток, перетаскивание, примагничивание, проверка победы.
- Адаптивная раскладка поля и лотка под 20:9 и 4:3, скрытие уровней с кусочками мельче 48 dp.
- Отрисовка кусочков в изображения при нарезке, прокручиваемый лоток, сохранение незаконченного пазла.
- Экран победы: анимация, звезда, кнопки «ещё раз» и «следующая».

Готово, когда: любую картинку можно собрать на всех уровнях, доступных на устройстве (на планшете — на всех четырёх); тесты нарезки покрывают все сетки; на слабом телефоне в профильном режиме (`flutter run --profile`) пазл из 48 кусочков держит 60 FPS.

### Этап 2. Каталог, навигация, прогресс

- Главный экран с категориями, экран картинок категории, выбор сложности.
- Загрузка встроенного манифеста, отметки собранных картинок, хранение прогресса.
- Настройки: звук, музыка, подсказка-подложка, язык.
- Минимальная настройка Play Console для закрытого тестирования, загрузка первой сборки, набор 15–25 тестировщиков.

Готово, когда: можно пройти путь «категория → картинка → сборка → возврат» с сохранением прогресса после перезапуска; сборка загружена в закрытое тестирование, и 14-дневный отсчёт начался.

### Этап 3. Картинки

- Style guide по эталону `docs/puzzle_refs/style_anchor.png`, `animals.csv` со списком для всех 11 категорий без пересечений.
- Скрипты генерации через Nano Banana 2 Lite с эталонами, отбора, обработки (обрезка, ресайз, WebP) и обновления манифеста в `tools/image_pipeline/`.
- Пробная партия 5–10 картинок из разных категорий с проверкой на планшете, затем первая категория целиком (например, sea), затем остальные по 20 картинок.
- Замена шести временных картинок в `assets/images/free/` на финальные по тем же id.

Готово, когда: 220 картинок прошли чек-лист, 55 бесплатных лежат в assets, у каждой категории есть эталон, манифест валиден.

### Этап 4. Доставка контента

- Загрузка свежего манифеста с CDN с откатом на встроенный.
- Скачивание платных картинок по запросу, проверка sha256, кэш на диске, индикатор загрузки, обработка отсутствия сети.

Готово, когда: платная картинка скачивается один раз, дальше открывается офлайн; битый файл перекачивается.

### Этап 5. Полная версия (разовая покупка)

- Интеграция RevenueCat, entitlement `full`, разовый продукт `full_version` за $4.99, пейволл, родительский контроль, восстановление покупок.
- Замки на закрытых картинках (размытые превью), реакция на изменение статуса покупки.

Готово, когда: лицензионный тестировщик покупает полную версию, получает доступ ко всем картинкам, после переустановки доступ возвращается (автоматически или через «Восстановить покупки» — по фактическому поведению RevenueCat) и пропадает после возврата денег.

### Этап 6. Полировка

- Звуки, музыка, анимации переходов, конфетти, вибрация.
- Проверка полноты перевода uk, en и ru, первый запуск без лишних экранов.
- Политика конфиденциальности и экран «О приложении».

Готово, когда: нет экранов с заглушками, все строки и названия всех категорий и картинок есть на трёх языках.

### Этап 7. Тестирование и подготовка релиза

- Прогон матрицы устройств, повторная проверка производительности на слабом телефоне (60 FPS при 48 кусочках), контроль размера AAB.
- Подписанный релизный AAB, R8 и обфускация, метаданные стора.

Готово, когда: релизная сборка загружена в закрытое тестирование, а 14 дней тестирования с 12+ тестировщиками, начатые после Этапа 2, завершены или подходят к концу.

## Публикация в Google Play

Если аккаунт разработчика личный и создан после 13 ноября 2023 года, перед выходом в продакшн нужно закрытое тестирование: минимум 12 тестировщиков, которые непрерывно участвуют последние 14 дней ([Google Play Console Help](https://support.google.com/googleplay/android-developer/answer/14151465?hl=en-EN)). Аккаунты организаций от этого требования освобождены, но для них нужен номер D-U-N-S, получение которого может занять до 30 дней ([Choicely](https://www.choicely.com/blog/google-play-12-tester-rule)). На первый запуск с личного аккаунта стоит заложить около трёх недель. Чтобы они не ушли на ожидание, закрытое тестирование начинается сразу после Этапа 2.

Что подготовить:

- [ ] Аккаунт разработчика и платёжный профиль (нужен для платных покупок)
- [ ] Внутреннее тестирование для себя и закрытое тестирование с запасом 15–25 тестировщиков, чтобы пережить отвалы
- [ ] Политика конфиденциальности по публичному URL
- [ ] Раздел «Целевая аудитория и контент»: если в целевую аудиторию входят дети, приложение попадает под политику Google Play для семей, что влияет на рекламу, аналитику и сбор данных
- [ ] Форма безопасности данных (Data safety) с учётом RevenueCat и Firebase
- [ ] Возрастной рейтинг (анкета IARC)
- [ ] Карточка стора: иконка, баннер, скриншоты для телефона и планшетов, описание на uk, en и ru
- [ ] Список стран распространения: только страны, где доступна оплата в Google Play
- [ ] Разовый продукт `full_version` создан и активен до отправки на ревью

## Как запускать в Claude Code с oh-my-claudecode

Этот документ скачивается как Markdown и кладётся в папку проекта как `docs/PLAN.md`; агенты выполняют его по одному этапу, а не целиком за раз.

oh-my-claudecode (OMC) — плагин мультиагентной оркестрации для Claude Code ([OMC на GitHub](https://github.com/Yeachan-Heo/oh-my-claudecode)). Установка из Claude Code:

```
/plugin marketplace add https://github.com/Yeachan-Heo/oh-my-claudecode
/plugin install oh-my-claudecode
/oh-my-claudecode:omc-setup --local
```

Порядок работы:

1. Положить в проект `docs/PLAN.md` и короткий `CLAUDE.md`: стек, структура папок, правила (Riverpod, без логики в виджетах, тесты для нарезки и прогресса, `flutter analyze` без предупреждений).
2. Запускать по одному этапу с явной ссылкой на критерий «Готово, когда», например: `autopilot: выполни Этап 1 из docs/PLAN.md, критерии приёмки в конце этапа`.
3. После каждого этапа самому запустить приложение на эмуляторе телефона и планшета, проверить критерий и только потом переходить дальше.
4. Этап 3 (картинки) вести в отдельной сессии: скрипты пишет Claude Code, а запуск генерации, отбор и ручная проверка за вами.
5. Ключи API генератора, RevenueCat и CDN — только в переменных окружения и файле `.env`, который не входит в ассеты приложения.

Перед стартом проверьте актуальные режимы и команды OMC в его README: проект быстро меняется.
